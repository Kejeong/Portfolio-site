팔레트의 주문 흐름에는 **상품과 주문을 함께 잠가야 하는 작업**이 여러 개 있습니다. 주문 생성, 주문 취소, 그리고 스케줄러가 처리하는 결제 만료입니다. 판매자가 상품을 판매 중지하거나 삭제하면 그 상품이 담긴 결제 전 주문을 취소하고 재고를 되돌려야 해서, 이 작업도 상품과 주문을 함께 잠급니다.

## 문제: 경로마다 잠그는 순서가 달랐다

작업마다 상품과 주문을 잠그는 순서가 달랐습니다.

| 작업 | 잠그는 순서 |
| --- | --- |
| 주문 생성 | 상품(재고 차감) → 주문 |
| 판매 중지·삭제로 인한 주문 취소 | 주문 → 상품(재고 복원) |
| 결제 만료 취소 | 주문 → 상품(재고 복원) |

두 작업이 동시에 실행되면 한쪽은 상품을 잡고 주문을 기다리고, 다른 쪽은 주문을 잡고 상품을 기다리게 됩니다. 서로가 가진 잠금을 기다리며 멈추는 **전형적인 교착 상태**입니다.

```text
트랜잭션 A (주문 생성)          트랜잭션 B (판매 중지로 취소)
상품 1 잠금 ✔                   주문 10 잠금 ✔
주문 10 잠금 대기 …             상품 1 잠금 대기 …
            ↑──────── 서로 기다림 ────────↑
```

## 고민: 감지하고 재시도할까, 처음부터 막을까

DB는 교착을 감지하면 한쪽 트랜잭션을 강제로 실패시킵니다. 그 실패를 잡아 다시 시도하는 방법도 있지만, 선택하지 않았습니다.

- **재시도의 한계**: 재고 차감, 주문 취소처럼 돈과 재고가 걸린 작업에서 "가끔 실패하고 다시 하는" 흐름은 예측하기 어렵습니다. 재시도 로직이 경로마다 흩어지는 것도 부담이었습니다
- **순서 고정**: 모든 경로가 같은 순서로만 잠그면 서로를 기다리는 고리 자체가 생기지 않습니다. 교착이 **생길 수 없게** 만드는 쪽을 골랐습니다

## 해결: 모든 경로를 상품 → 주문으로

잠금 순서 규칙은 한 가지입니다.

- **상품 먼저**: 상품이 여러 개면 ID 오름차순으로 정렬해서 잠급니다
- **주문은 그다음**: 상품을 모두 잠근 뒤에만 주문을 잠급니다

판매 중지·삭제로 인한 주문 취소도 이 규칙에 맞춰 **상품 → 주문** 순서로 바꿨습니다. 함께 처리한 것도 있습니다.

- **잠그기 전에 거르기**: 본인 주문이 아니거나 없는 주문이면 상품을 잠그지 않고 바로 끝냅니다. 쓸데없이 잠금을 잡지 않기 위해서입니다
- **다른 판매자와 겹칠 때**: 다른 판매자가 동시에 상품을 중지·삭제해서 잠금을 얻지 못하면, 예외로 처리해 전체가 멈추지 않게 했습니다

## 규칙이 깨지지 않게

순서 규칙은 코드에 한 번 적어 두는 것만으로는 지켜지지 않습니다. 새 기능이 생기면서 다른 순서로 잠그는 코드가 들어오기 쉽습니다.

- **단위 테스트로 고정**: 각 경로가 상품을 ID 오름차순으로 잠근 뒤 주문을 잠그는지 테스트로 확인합니다. 순서가 바뀌면 테스트가 깨집니다
- **스케줄러는 건 단위로**: 결제 만료와 자동 구매 확정은 id 커서로 나눠 **한 건씩 각자 트랜잭션**으로 처리합니다. 한 번에 여러 주문을 오래 잡고 있지 않고, 한 건이 실패해도 다른 주문에는 영향이 없습니다

## 함께 다룬 동시성 문제

교착과 함께 같은 주문을 두 작업이 동시에 건드리는 문제도 풀었습니다. 자세한 내용은 각각 글로 정리했습니다.

- **결제, 취소, 만료 중 하나만**: 만료 직전에 들어온 결제와 만료 스케줄러가 겹쳐도 하나만 반영되게 했습니다 ([비관적 락 글](/blog/pessimistic-lock-expiry))
- **같은 주문 요청이 여러 번 와도 하나만**: 중복 클릭이나 재시도로 재고가 여러 번 빠지지 않게 했습니다 ([멱등성 글](/blog/order-idempotency))

## 정리

| 고민 | 선택 |
| --- | --- |
| 경로마다 잠금 순서가 다르다 | 모든 경로를 상품(ID 오름차순) → 주문으로 고정 |
| 감지 후 재시도 vs 순서 고정 | 교착이 생길 수 없게 순서 고정 |
| 쓸데없는 잠금 | 잠그기 전에 본인 주문인지 먼저 확인 |
| 규칙이 깨질 수 있다 | 잠금 순서를 단위 테스트로 지킴 |
| 스케줄러가 잠금을 오래 잡는다 | id 커서와 건 단위 트랜잭션 |
